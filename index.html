Correction, 2026-10-07

A look-ahead leak in my own published value factor

After publishing, I found a look-ahead leak in my own value factor: earnings per share as filed were divided by prices adjusted for every later stock split (and, more mildly, later dividends), inflating each stock's earnings yield by its own future split factor. I corrected the engine, re-ran the full pre-registered grid, and published the correction with the original numbers kept beside the new ones.

+0.0111 → −0.0051 value-factor IC t = 1.26 → −0.48 IC t-statistic 3 of 8 → 0 of 8 ML configs beating baseline 0.066 → −0.174 baseline OOS Sharpe

The apparent ML edge disappeared entirely. The null result survived and got stronger.

Independent Research, 2026

Does Machine Learning Beat a Linear Factor Combination? A Pre-Registered, Cost-Aware Test

Published 2026-09-23 • Corrected 2026-10-07

Built on my multi-factor backtesting framework (see Projects).

QuestionCan ML (gradient boosting / random forest) combine momentum, value, and quality into a better long–short signal than an equal-weight linear composite — out-of-sample, US large-caps, after costs?

DesignPre-registered null hypothesis: ML does not beat the linear composite OOS after costs. Same universe, same 8 bps cost model, walk-forward training with purge/embargo, judged on Sharpe, deflated Sharpe, drawdown, and turnover.

ResultThe pre-registered null holds. Every one of the 8 ML configurations is worse than the linear baseline out of sample after costs: ML Sharpe −0.590 to −0.361, against −0.174 for the baseline. Zero of eight beat it.

This is the corrected result. After publishing, I found and fixed a look-ahead leak in my own value factor (see Correction); the original numbers are kept beside the new ones.

Quant Research

Factor Backtester Flagship

A pip-installable Python library (v1.0.0) for backtesting long-short S&P 500 factor strategies on momentum, value, and quality, with a factor-backtest CLI and a plugin registry where a new factor is one dropped file. It handles point-in-time universe construction, delisted names, realistic trading costs, walk-forward validation, and deflated Sharpe analysis.

  • Found and fixed two correctness bugs in my own engine: it could hold delisted stocks in months they never traded, and a split-basis look-ahead leak in the value factor was worth about 0.17 of Sharpe
  • Refactored a 704-line data-access module into typed provider Protocols (Yahoo, Tiingo, SEC EDGAR); a new data source is one file implementing one interface
  • Every run reports gross, flat 8 bps, and per-name cost models side by side, so the cost assumption is shown rather than asserted
  • 153 pytest tests; CI runs ruff, mypy, and pytest across a pandas 2.x / 3.x matrix. Docker image, MIT license
2010-2024 test window 8 bps per-trade cost model 153 pytest tests −0.16 out-of-sample Sharpe

Correcting those two bugs moved the out-of-sample Sharpe from 0.02 to −0.16. The naive factor mix has no edge, and costs are not the reason: gross of costs it is still −0.14. That is the point of the work: build research infrastructure that can reject weak ideas instead of dressing them up.
